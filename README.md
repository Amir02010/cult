# CULT RESTAURANT — онлайн-меню

Онлайн-меню ресторана по макету CULT: тёмная премиальная тема, три языка (RU / EN / UZ),
корзина, админ-панель и **приём заказов только внутри ресторана** — по геопозиции,
с проверкой на сервере.

- **Клиент:** Create React App (`react-scripts`), JavaScript + JSX + CSS.
  Никакого Vite, Next.js и TypeScript.
- **Сервер:** Node.js + Express, база — JSON-файл (`server/data/db.json`).
- Шрифты подключены локально (`@fontsource`), поэтому меню открывается даже
  при плохом интернете в зале.

## Быстрый старт

```bash
npm run install:all      # ставит зависимости в корне, в server/ и в client/
npm start                # поднимает API и сайт одной командой
```

Адреса печатаются при запуске:

- Сайт: <http://localhost:3000>
- Админ-панель: <http://localhost:3000/admin>
- API: <http://localhost:4000/api>

**Если порт 3000 занят** (Skype, другой проект, забытый процесс) — сайт
автоматически стартует на 3001, 3002 и так далее, ничего освобождать не нужно.
Порт API фиксирован: 4000. Посмотреть, кто и что занимает, и как это закрыть:

```bash
npm run ports
```

**Доступ к меню.** Сейчас меню открыто всем: заходите с любого компьютера и
телефона, заказ оформляется без проверки геопозиции. Координаты ресторана уже
записаны (39.674798, 66.929873, радиус 120 м) — защита просто выключена.

```bash
npm run open   # меню видно всем, заказ без геопроверки (сейчас так)
npm run lock   # сайт и заказ работают только в зале ресторана
npm run reset  # начать базу с нуля (старая сохранится рядом как backup)
```

После `npm run open` / `npm run lock` перезапустите сервер (Ctrl+C и снова
`npm start`). То же самое переключается в админке: **Настройки → Зона заказа**.

Логины по умолчанию (**смените их в «Настройки → Смена пароля»**):

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin` | `cult2026` |
| Официант | `waiter` | `cult1234` |

Отдельно:

```bash
npm run start:server     # только API
npm run start:client     # только CRA
npm run build            # production-сборка клиента в client/build
```

После `npm run build` сервер сам отдаёт собранный сайт — для продакшена достаточно
одного процесса:

```bash
npm run build && npm run serve   # всё на http://localhost:4000
```

## Как устроена защита «заказ только в ресторане»

Главное правило: **клиенту нельзя верить**. Браузер лишь сообщает координаты,
а решение принимает сервер.

1. Гость открывает меню. Браузер запрашивает геопозицию.
2. Координаты уходят на `POST /api/geo/verify`. Сервер считает расстояние до
   ресторана (формула гаверсинусов) и сравнивает с радиусом из настроек.
3. Если гость внутри радиуса — сервер выдаёт **подписанный токен** (JWT, живёт 20 минут)
   и привязывает его к идентификатору устройства.
4. `POST /api/orders` принимает заказ **только** с валидным токеном. Сервер заново
   проверяет координаты из токена по актуальным настройкам и сверяет устройство.

Что это даёт на практике:

- Ребёнок сфотографировал QR-код и сканирует его дома → меню откроется, но корзина
  и кнопка «Оформить заказ» заблокированы: он вне радиуса.
- Правка `allowed: true` в консоли браузера ничего не даёт — токена всё равно нет,
  сервер ответит `geo_required`.
- Токен, переданный на другое устройство, отбрасывается (`geo_device_mismatch`).
- Цены берутся из базы, а не из запроса: подменить сумму в корзине нельзя.

Дополнительный фильтр — **максимальная погрешность**. Если браузер сообщает точность
хуже указанной (например ±3000 м — позиция определена по IP или вышке), заказ
отклоняется, даже когда «центр» позиции попал в радиус. Рекомендуемое значение 50–100 м.

### Зона ресторана

Координаты заведения уже прописаны:

| Параметр | Значение |
|---|---|
| Широта | `39.674798` |
| Долгота | `66.929873` |
| Радиус | `120` м |
| Режим доступа | `onsite` — сайт работает только в зале |

Если точку нужно уточнить (например, взять центр зала вместо угла здания) —
встаньте в ресторане, откройте админку с телефона и нажмите
**Настройки → Зона заказа → «Взять мои координаты» → «Сохранить»**.

Если однажды очистить координаты, зона считается ненастроенной: проверка
отключается, сайт работает как обычно, а в админке появляется предупреждение.
Это защита от того, чтобы случайно не закрыть самому себе доступ.

Чтобы включить защиту:

1. Придите в ресторан, встаньте в зале.
2. Откройте админку с телефона → **Настройки → Зона заказа**.
3. Нажмите **«Взять мои координаты»** → **«Сохранить настройки»**.

Всё. Координаты записаны с точностью GPS, защита включилась сама. Радиус по
умолчанию 120 м — хватает на зал и террасу.

Вручную координаты вписывать не нужно, но поля доступны, если захотите взять
точку с карты.

### Два режима доступа

**Настройки → Что видит гость вне ресторана:**

| Режим | Вне радиуса | Внутри |
|---|---|---|
| Меню открыто всем | меню видно, кнопка заказа заблокирована | всё работает |
| **Сайт работает только в зале** (включён) | сайт не открывается: экран «Меню доступно только в ресторане» | всё работает |

Во втором режиме сервер вообще не отдаёт блюда без подтверждённой геопозиции —
блокировка настоящая, а не косметическая.

Прежде чем включать строгий режим, взвесьте: меню не увидят те, кто ищет вас в
интернете, поисковики его не проиндексируют, а гость с выключенным GPS не увидит
ничего и позовёт официанта. Админ-панель доступна всегда — заблокировать себя
нельзя.

### QR-код

По умолчанию используется **один QR-код на весь зал** — он ведёт на `/menu`,
а номер столика гость выбирает сам при оформлении заказа. Скачать для печати:
**QR и столы → Скачать PNG для печати**.

Если позже захотите отдельный код для каждого стола (тогда столик подставится
автоматически) — включите переключатель «Отдельный QR на каждый стол» на той же
странице. Такие коды ведут на `/t/A3`.

В обоих случаях QR — это **удобство, а не пропуск**: право оформить заказ даёт
только геопозиция.

## Анимация

Всё движение — декорация: вёрстка читается корректно и с полностью выключенной
анимацией. Флаг `prefers-reduced-motion` в системе гостя отключает всё разом.

**Интро с драконом.** При первом заходе за сессию дракон из макета влетает слева,
кружит на месте, пока грузится меню, и улетает вправо. Дракон — реальный элемент
макета (`public/images/dragon.png`, вырезан по тёплому каналу с прозрачностью),
а не сторонняя картинка. Минимальное время показа 1,5 с: интро, мелькнувшее за
80 мс, читается как сбой. В строгом режиме дракон продолжает кружить, пока
проверяется геопозиция, — экран блокировки не мелькает по дороге.
Интро запоминается в `sessionStorage` и не повторяется при переходах, а в
админ-панели не показывается вовсе.

**Звук вылета.** Когда дракон улетает, играет короткий взмах крыльев с уходящим
вдаль рыком — `public/sounds/dragon-fly.mp3`, 1,9 с, 27 КБ, синтезирован под этот
проект. Гость может выключить звук кнопкой на самом интро или в боковом меню,
выбор сохраняется.

Важное ограничение браузеров: **звук не играет, пока гость не коснулся страницы**.
Это правило Chrome и Safari, обойти его нельзя. Поэтому при холодном открытии
(гость отсканировал QR — и сразу меню) сайт сначала молча спрашивает у браузера
разрешение; если его нет, под логотипом появляется подсказка «Коснитесь экрана —
со звуком», и интро держится 2,6 с вместо 1,5 с. Касание разблокирует звук и
сразу отправляет дракона в полёт — то есть тап не задерживает гостя, а ускоряет.
Если гость не коснулся, дракон улетает молча: тишина здесь правильное поведение,
а не ошибка.

**Карточки блюд** наклоняются к курсору (`useTilt`): фото поворачивается,
блик следует за указателем, цена и кнопка приподняты над поверхностью
(`translateZ`). На тач-экранах эффект выключен — там наводить нечем.

**Остальное:** появление секций при скролле (`useReveal`), блик по кнопкам,
пульс на счётчике корзины при добавлении, плавная смена страниц, счётчики в
дашборде, которые докручиваются до нового значения.

Всё это живёт в `src/styles/motion.css` и двух хуках в `src/hooks/`.

## Админ-панель

| Раздел | Что можно |
|---|---|
| Дашборд | заказы и выручка за день, средний чек, топ блюд, последние заказы |
| Заказы | лента в реальном времени, статусы `новый → принят → готовится → подан`, отмена, расстояние гостя от ресторана |
| Меню | категории и блюда: создание, правка, удаление, порядок, видимость, «хит», загрузка фото, все три языка |
| QR и столы | общий QR-код зала, столы и зоны, при необходимости — отдельный QR на стол |
| Настройки | геозона, данные заведения, валюта, часы, смена пароля |

Роли: **администратор** видит всё; **официант** — только дашборд, заказы и столы.

## Полезно знать

- **Сбросить всё к исходному состоянию:** удалите `server/data/db.json` и перезапустите сервер.
- **Изображения** блюд взяты с макета и намеренно помечены как заменяемые —
  загрузите свои через «Меню → блюдо → Загрузить файл». Файлы лягут в `server/uploads/`.
- **Секреты.** Перед публикацией в интернет задайте переменные окружения:

  ```bash
  AUTH_SECRET=...   # подпись токенов админки
  GEO_SECRET=...    # подпись гео-токенов
  PORT=4000
  ```

- **HTTPS обязателен** на боевом домене: браузеры не отдают геопозицию по `http://`
  (кроме `localhost`).
- **Другие порты:** `PORT_WEB` и `PORT_API` меняют порты запуска, например
  `PORT_API=5000 npm start` (в PowerShell: `$env:PORT_API=5000; npm start`).
  Если меняете порт API — поправьте `client/.env.development`.
- **Открыть dev-сайт с телефона в одной сети:** замените в
  `client/.env.development` `localhost` на IP компьютера. Учтите, что геопозиция
  по `http://` всё равно не работает — для проверки геозоны нужен HTTPS.
- Валюта, адрес, слоган и часы работы правятся в админке и сразу видны на сайте.

### Vercel

Vercel показывает меню как витрину: сервера там нет, поэтому перед сборкой
`scripts/snapshot.js` кладёт рядом со статикой снимок меню, и сайт берёт меню
из него. Заказ и админка на Vercel не работают — им нужен живой сервер.

В `vercel.json` правило отдаёт приложению все внутренние адреса
(`/menu/pizza` и т.п.), **кроме `/api/`**. Это намеренно: запрос к `/api/menu`
должен честно получить 404 — по этому провалу сайт и переключается на снимок.
Если отдать на него html-страницу, сайт примет её за меню и упадёт.

`client/vercel.json` — запасной на случай, если в настройках проекта
Root Directory указан `client`: тогда корневой файл Vercel не читает.

В `vercel.json` нельзя писать комментарии и лишние поля: Vercel проверяет файл
по строгой схеме и отклоняет развёртывание целиком.
